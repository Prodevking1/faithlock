## Bottom nav — fix laggy tab-switch recolor
- Bug: switching tabs left the previous tab's color lingering for a moment. Root cause: `HugeIcon` renders via `SvgPicture.string` and regenerates+re-parses the SVG **asynchronously** whenever its color/strokeWidth changes, showing the stale picture during the gap. We were changing both color and `strokeWidth` (2.4↔1.8) on every selection.
- Fix: new `CozyNavIcon` widget in `cozy_bottom_nav.dart` renders the `HugeIcon` with a **constant** color (black) + constant stroke (2.0), and applies the active/inactive tint via `ColorFiltered(ColorFilter.mode(color, BlendMode.srcIn))`. The SVG string never changes → parsed once → recolor is instant at the compositing layer. The 4 `main_screen.dart` builders now return `CozyNavIcon` instead of a directly-colored `HugeIcon`.
- Tradeoff: dropped the per-state stroke thickness (active was 2.4); active state is still conveyed by the orange tint + bold label. `flutter analyze` clean.

## Prayer player — ElevenLabs audio + Replicate forced alignment (exact karaoke sync)
- User reverted the flutter_tts switch: wants the ElevenLabs MP3 quality back but with **exact** word sync. Researched options — settled on **Replicate `cureau/force-align-wordstamps`** (stable-ts/faster-whisper under the hood; takes audio + transcript, returns `{words:[{word,start,end}]}` in seconds). User already runs the prayer pipeline on Replicate, so adding an `align` phase reuses the same toolchain + .env.
- **Data model**: `Prayer.wordTimings: List<WordTiming>?` added. `WordTiming` stores `startMs`/`endMs` ints internally; the `fromMap` accepts both the raw Replicate shape (`start`/`end` seconds) and the canonical storage shape (`start_ms`/`end_ms`). `Prayer.fromMap`/`toMap` round-trips `word_timings` through Supabase jsonb.
- **Controller**: `PrayerPlayerController` rewritten with an engine selector. Picks `_AudioEngine` (just_audio + binary-search lookup on word timings, exact sync) when both `audio_path` AND `wordTimings` are present; falls back to `_TtsEngine` (the existing flutter_tts loop, estimated sync) otherwise. Both engines write into the same Rx surface (`activeIndex`, `wordStart`, `wordEnd`, `elapsed`, `total`, `isPlaying`, `isFinished`), so `SyncedScriptReader` needs zero changes. `_AudioEngine` builds a word→segment map at prepare time (best-effort fuzzy match on lowercased letters so Replicate's punctuation variants don't break the sequence) and uses the position stream to derive both the active line and the karaoke char range.
- **Pipeline** (`scripts/prayer_pipeline/`): new `align` phase added to `generate.mjs`. Fetches each prayer's `audio_path`+`script_text` from Supabase, mints a signed URL, calls Replicate `cureau/force-align-wordstamps`, polls, normalises seconds→ms, and `update`s `prayers.word_timings`. `npm run align` (or `npm run all` which now does `text → audio → upload → align`). Retrofits existing prayers via `--only=<id>`. New env: `REPLICATE_ALIGN_MODEL` (defaults to `cureau/force-align-wordstamps`).
- **Schema** (`schema.sql`): added `word_timings jsonb` column with an idempotent `alter table ... add column if not exists` for already-provisioned DBs.
- `flutter analyze` clean for the model + controller. `node --check` clean on the pipeline. **Next steps for user**: run the updated `schema.sql` in Supabase SQL editor (idempotent), then `npm run align` to backfill the `word_timings` column for existing prayers.
