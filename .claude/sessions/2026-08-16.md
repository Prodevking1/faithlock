# 2026-08-16

## Live Activity « offre promo 1ère semaine à 1 $ » (Dynamic Island)

Implémenté le cas 2 de `docs/live-activities-plan.md`, revu à la lumière de la
recherche : l'HIG Apple interdit explicitement les Live Activities publicitaires
(« Don't use a Live Activity to display ads or promotions »), Duolingo s'est fait
épingler dessus en janvier 2026 sans être retiré de l'App Store.

**Décision structurante** : ne pas faire démarrer la Live Activity toute seule.
Elle ne démarre que sur un tap explicite (« Reserve mine »), suit une vraie
échéance persistée, ne se relance jamais, meurt à l'achat/au dismiss, et est
derrière un flag PostHog coupable à distance. C'est ce qui la rend défendable en
review — ne pas « simplifier » en la déclenchant au lancement.

**Fenêtre à 8 h, pas 24 h** : ActivityKit tue une activité après 8 h. Un compteur
de 24 h disparaîtrait aux deux tiers de sa course.

**Fichiers** : Swift dans `ios/FaithLockWidget/PromoOffer*.swift` +
`ios/Runner/LiveActivityBridge.swift` ; Dart dans `lib/services/live_activity/`
et `lib/features/paywall/` (controller, screen cozy, carte d'entrée home).
Doc complète + plan d'A/B test : `docs/dynamic-island-promo-offer.md`.

**Effet de bord assumé** : `DeepLinkService.initialize()` était commenté dans
`main.dart` — réactivé, sinon le tap sur la Live Activity ne route nulle part
(et les liens de notification prière/unlock non plus). À surveiller au 1er run.

**Env** : `/usr/local/bin/pod` (shim gem mort) masque le CocoaPods Homebrew
fonctionnel. Contournement : `PATH="/opt/homebrew/bin:$PATH"`. Rien installé.

**Vérifié en live** (simulateur iPhone 17 Pro / iOS 26.2) : Live Activity démarrée
via le bridge (`✅ activity started (id=…)`) et **rendue dans la Dynamic Island**
(🎁 + compteur qui décompte) ; page d'offre cozy conforme. Pas capturé : écran
verrouillé et DI expanded (demandent un contrôle tactile — le serveur computer-use
de cette machine renvoie `not_installed` pour toute app, même Finder).

**2 bugs trouvés PAR le test, corrigés** :
1. `Purchases.getOfferings()` avant `Purchases.configure` = `fatalError` Swift,
   non rattrapable côté Dart → l'app meurt. Atteignable en prod (tap LA à froid,
   ou init RevenueCat en échec). Fix : `_waitForRevenueCat()` puis état d'erreur.
2. Prix d'intro affiché brut → « $0.00 for 7 days » sur un produit à essai
   gratuit. Fix : `introPrice`/`introPeriod`/`offerSummary` dérivés de StoreKit.

**Piège d'env** : `shared_preferences` iOS n'écrit PAS dans le domaine `defaults`
du simulateur mais dans le plist du conteneur de données de l'app. Semer une
valeur via `defaults write com.appbiz.faithlock` ne fait rien pour l'app.

**Fallback debug** : sans le flag PostHog, release → `control` (rien ne s'affiche),
debug → `gift` — sinon la feature est intestable avant la création du flag.
Ajout de l'override QA `--dart-define=PROMO_LA_VARIANT=gift` : un build debug
**refuse de se lancer seul sur un device** (« can only be launched from Flutter
tooling »), donc le test device passe par un build profile, où `kDebugMode` est
faux. Vide par défaut → aucun effet sur une release.

**Device (iPhone 15 Pro, iOS 26.5)** : build profile installé via `devicectl`,
réservation créée depuis la carte 🎁 (prefs device : `promo_la_reserved_at`
13:42, variante `gift`), relance sans nouvel event → `restoreIfNeeded()` sort sur
`isRunning`, l'activité tourne déjà. Idempotence confirmée sur device.
Lire les prefs d'un device : `devicectl device copy from --domain-type
appDataContainer --domain-identifier com.appbiz.faithlock`.
