## Bible — critical data bug fixed + UI consistency cleanup (3-agent audit)
Spawned three parallel Explore agents to audit (1) data layer, (2) UI consistency, (3) localization. Findings + fixes applied:

### Fix #1 — Book name normalization (CRITICAL — was breaking 18 books in prod)
- Bug: BSB DB stores numbered books with Roman numerals (`I Samuel`, `II Kings`, `III John`) and Revelation as `Revelation of John`; Dart `kBibleBooks` uses Arabic numerals + `Revelation`. The repo passed Dart names straight to the SQL `WHERE b.name = ?`, returning 0 verses for ~26% of books. The silent `catch (_)` in `BibleController.versesFor` masked it.
- Fix: added `_displayToDbBookName` + reverse map in `bible_repository.dart` and exposed two public static helpers `BibleRepository.dbBookName()` / `displayBookName()`. Normalized at every boundary: WHERE inputs in `bible_repository.dart` and `bible_database_loader.dart`, plus `book_name` SELECT outputs in the 3 result-builder loops in `bible_database_loader.dart` (so the UI never sees "I Samuel" / "Revelation of John"). 18 books now resolve correctly: 1/2 Samuel, 1/2 Kings, 1/2 Chronicles, 1/2 Corinthians, 1/2 Thessalonians, 1/2 Timothy, 1/2 Peter, 1/2/3 John, Revelation.

### Fix #2 — Surface errors in `versesFor`
- `bible_controller.dart`: replaced silent `catch (_)` with `debugPrint` of `bookName/chapter/versionAbbr/error` + stack trace. Future data-side regressions will be visible in dev logs instead of looking like "empty chapter".

### Fix #3 — Localize 22 hardcoded English strings in Bible UI
- New `bible_*` localization namespace in all 5 locales (en/fr/de/ja/pt): `holyBible`, `searchBooks`, `noVersesAvailable`, `readingMode`, `availableVersions`, `bibleVersion`, `thoughtTitle`, `heartsNote`, `reflectionTitleHint`, `reflectionNoteHint`, `saveReflection`, `reflection`, `verseHighlighted`, `highlightRemoved`, `verseBookmarked`, `bookmarkRemoved`, `chapterBookmarked` (with `@reference` param), `toolbarCopy`, `toolbarHighlight`, `toolbarBookmark`, `toolbarShare`, `toolbarReflect`. UPPERCASE labels in the UI (`AVAILABLE VERSIONS`, `THOUGHT TITLE`, etc.) use `.tr.toUpperCase()` so non-Latin locales aren't forced to manually casing.
- Patched 5 screens: `cozy_bible_home_screen`, `cozy_book_detail_screen`, `cozy_version_selection_sheet`, `cozy_reflection_note_screen`, `cozy_reading_screen` (snackbars + toolbar labels).

### Fix #4 — Unified verse reference casing
